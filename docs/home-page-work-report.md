# Отчет о выполненных работах по главной странице CRM

## Цель работ

В рамках доработки CRM-системы для малых банковских предприятий была реализована главная страница приложения. До начала работ основной функционал системы уже был готов, но стартовая страница оставалась пустой и не отражала ценность продукта для пользователя.

Целью доработки было создать рабочий экран, который помогает менеджеру быстро оценить состояние клиентской базы, сделок и банковских продуктов, а также удобно перейти к основным действиям в системе.

## Реализованная главная страница

Главная страница оформлена как рабочий стол менеджера. Она не является рекламной или статичной страницей, а использует данные CRM и показывает актуальное состояние системы.

На странице размещены следующие блоки:

- ключевые показатели по клиентам, компаниям, физическим лицам и сделкам;
- воронка сделок по этапам банковского процесса;
- портфель банковских продуктов;
- процесс обслуживания клиента;
- очередь внимания по приоритетным сделкам;
- быстрые действия для создания компании, физического лица и сделки.

Такой состав блоков позволяет использовать главную страницу как демонстрационный экран на защите проекта и как практический стартовый экран для ежедневной работы менеджера.

## Ключевые показатели

В верхней части страницы отображаются основные числовые показатели:

- клиентская база;
- количество компаний;
- количество физических лиц;
- количество сделок;
- количество открытых сделок;
- количество сделок, требующих внимания.

Эти показатели помогают быстро понять общий масштаб данных в системе и перейти в соответствующие разделы CRM.

## Воронка сделок

Воронка сделок показывает распределение сделок по этапам бизнес-процесса:

- лид;
- квалификация;
- подготовка предложения;
- согласование с клиентом;
- рассмотрение банком;
- подписание документов;
- выиграно;
- проиграно;
- отменено.

Блок позволяет оценить, на каких этапах находится основной объем работы. Например, если много сделок находится на этапе рассмотрения банком или подписания документов, менеджер видит, где требуется контроль сроков и дальнейшие действия.

После исправления проблемы с подсчетом записей на стороне API значения воронки отражают количество сделок именно по каждому этапу, а не общее количество сделок в системе.

## Портфель продуктов

Портфель продуктов показывает распределение сделок по банковским продуктам:

- расчетный счет;
- кредит;
- депозит;
- зарплатный проект;
- эквайринг;
- банковская гарантия;
- лизинг.

Этот блок помогает оценить, какие продукты чаще встречаются в работе менеджера и какие направления продаж представлены в CRM. После исправления подсчета записей по фильтрам значения в этом блоке показывают количество сделок по каждому конкретному продукту.

## Процесс обслуживания

Блок процесса обслуживания визуально показывает основной сценарий работы в CRM:

- регистрация и ведение клиента;
- работа с контактными лицами компании;
- создание сделки по банковскому продукту;
- контроль этапов, статусов и сроков.

Этот блок особенно полезен для презентации системы заказчику или комиссии, так как он кратко объясняет логику CRM и связывает отдельные разделы приложения в единый бизнес-процесс.

## Очередь внимания

Очередь внимания выводит открытые сделки с высоким или срочным приоритетом. Для каждой сделки отображаются:

- название или номер сделки;
- приоритет;
- банковский продукт;
- сумма;
- плановая дата закрытия.

Из этого блока менеджер может быстро перейти в карточку сделки и выполнить необходимые действия. Это делает главную страницу не только информационной, но и операционной.

## Работа с данными

Главная страница использует уже существующие механизмы получения данных. Для ее реализации не потребовалось создавать отдельный endpoint дашборда.

Данные собираются через существующие запросы реестров с фильтрами и пагинацией. Это позволило сохранить текущую архитектуру приложения и не усложнять backend-контракт.

Отдельно была исправлена проблема подсчета количества записей при применении фильтров: теперь API возвращает количество записей, соответствующих конкретному фильтру. Благодаря этому воронка сделок и портфель продуктов отображают корректные значения.

## Адаптивность и доступность

Страница реализована с учетом адаптивного интерфейса:

- на широких экранах контент располагается в двух колонках;
- левая колонка содержит воронку сделок и портфель продуктов;
- правая колонка содержит процесс обслуживания и очередь внимания;
- на узких экранах блоки перестраиваются в одну колонку.

Также учтены требования доступности:

- у основных разделов есть заголовки;
- интерактивные элементы доступны как ссылки или кнопки;
- декоративные иконки не мешают screen reader;
- прогресс-индикаторы имеют aria-атрибуты для чтения значений.

## Результат

В результате доработки пустая главная страница была заменена на полноценный рабочий стол CRM. Страница демонстрирует ключевую ценность системы: управление клиентами, банковскими продуктами и сделками в едином интерфейсе.

Главная страница теперь может использоваться:

- как стартовый экран менеджера;
- как аналитический обзор состояния CRM;
- как демонстрационный экран при защите проекта;
- как наглядное объяснение бизнес-процесса для заказчика.

## Проверка

После выполнения работ была проведена техническая проверка:

- приложение успешно собирается в development-конфигурации;
- тест главной страницы проходит успешно;
- локальный dev server отвечает корректно.

Известное ограничение production-сборки связано не с главной страницей, а с существующим ограничением размера initial bundle в конфигурации Angular. Это ограничение может быть скорректировано отдельно при подготовке production-поставки.
